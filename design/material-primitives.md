# Material interaction primitives

The searchable workspace chooser uses official Material Web 2.5.0 `md-dialog`, `md-list` and `md-list-item type="button"` controls. The application composes the trigger, independent regex-capable search, pagination, selected indication and persistence event. The dialog enters the browser top layer, avoiding clipping by workspace ancestors. Native Material list buttons handle pointer and Enter/Space activation, while the dialog owns Escape, focus trapping and focus restoration. Choice filtering never changes the stored selection.

`mg-color-field` is an application color-editor composition, not an upstream color picker. Its six-digit hexadecimal editor is an official `md-outlined-text-field`; red, green and blue channels are official `md-slider` controls. Invalid text shows a field error and emits no persistence event. Valid text and completed slider changes emit `value-change` containing a lowercase six-digit hexadecimal color. The public `value`, `label`, `settings` and `disabled` properties allow reuse in settings and inline preferences. It does not invoke the operating-system color picker.

`mg-icon` renders locally bundled official Google Material Symbols outlined 24px geometry. Exact pinned revision, source SVGs and Apache-2.0 license are in `assets/material-symbols/`. Runtime path data is checked against those originals. No font service or runtime network request is involved. Existing application icon names map to the nearest official symbol; the desktop splitter and custom image logo remain explicit application compositions.

Focused verification: `node --import tsx --test tests/material-primitives.test.ts` checks asset preservation and provenance. `node tests/material-primitives.browser.mjs` bundles the real components into an isolated headless Chromium fixture and exercises pointer and keyboard selection, pagination, filtering, empty state, Escape/focus return, hex validation, RGB slider changes and icon geometry. This fixture proves component behavior, not integrated native settings persistence or full application visual acceptance; those require the current built application tests.

Shadow-local default anatomy was also restored in account, API, converter, model, security, startup, task-support, Tools and updater surfaces. Removed overrides forced 8/12px control shapes, 32px text buttons and undersized control labels. Explicit user appearance records and functional data typography remain supported. Inline preference help now uses an official text button with expanded state and an associated collapsible text region.

A real Linux Electron Tools navigation profile identified unconditional structural appearance-identity calculation as the dominant renderer hotspot. Restoration now considers explicit and previously styled targets directly, calculating structural identities across all nodes only when a saved or scheduled generated identity needs matching. Clearing records still clears styles on previously marked targets. Unchanged stylesheet text is retained without emitting needless DOM mutations. The focused browser regression covers saved explicit/generated targets, schedule application/removal, cache deletion and repeated restoration. A fresh isolated real application launch after rebuilding opened Tools and captured successfully where the prior build timed out; final integrated shell acceptance remains separate.
