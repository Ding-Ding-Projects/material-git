Extensions, aliases and cloud workspaces use dedicated task surfaces. Their internal GitHub CLI identifiers select validated adapters; they are not a user-facing command catalogue. The main-process service owns argument construction and exact, expiring reviews. The renderer receives descriptive choices and operation snapshots, never an unrestricted executable or environment editor.

Extension discovery searches the real GitHub gh-extension repository topic with twenty results per page, through GitHub search pagination. Installed extensions come from the actual local extension list. Create chooses the official script, Go or other-binary scaffold; install selects a remote repository or a workspace-contained local extension and optional pinned revision; upgrade exposes one/all, dry-run and force choices; remove and execute use installed extension identities. Execution receives separate argument rows. Running or installing external code requires an explicit warning and exact review. The adapter cannot supply terminal input to interactive extensions.

Aliases have an installed list, deletion, a regular-alias editor choosing a genuine built-in command and separate argument values, and a native YAML import picker with bounded preview. The import file must be a regular file smaller than 64 KiB, is fingerprinted at review, checked again at apply, then imported from a private immutable snapshot. Imported shell aliases are explicitly identified as external code; importing them does not run them. The regular-alias editor does not create shell aliases. Existing YAML constructs are interpreted by the real CLI; malformed input produces the actual error.

Cloud workspaces select actual Codespaces, currently bounded by the CLI list limit of 100, and disclose this bound. SSH configuration export and fixed read-only diagnostic profiles use real gh codespace ssh. Profiles cover system, directory, storage, Git status, process list, memory, file list and identity. Code opens a real stable/Insiders/web editor. Jupyter starts the real CLI forwarding workflow and requires JupyterLab in the remote workspace. File copy has upload/download, adjacent native local file/folder pickers, literal remote paths and recursive selection. Local paths remain in the approved workspace; remote expansion is off by default and requires a specific external-code review warning. Forwarding uses composite remote/local port controls; visibility uses port and public/private/organization selectors. All ports are validated as 1–65535, local forwarding ports must be distinct, and public access receives an explicit warning. Forwarding and Jupyter sessions have a one-hour limit and cancellation.

Copilot availability means an executable really exists locally, found on PATH or the documented downloaded-CLI locations. The app never calls gh copilot without an installed executable and therefore never triggers its implicit download. Reviewed actions are installed help, installed version, and a noninteractive prompt with all tools denied. Account entitlement and network requirements are reported by the actual installed CLI. Different Copilot versions can reject unsupported arguments; such rejection is a real failed operation, never synthesized success.

Every operation is reviewed against main-process stored arguments; a review expires after five minutes, can be used once, and cannot accept replacement arguments during apply. Structured fields reject unknown keys, wrong types, invalid identifiers, oversized text, null bytes, unapproved paths and malformed ports. Execution uses shell:false, ignored stdin, disabled prompts, bounded UTF-8 output, streamed credential redaction and real exit status. Cancellation targets the process group on POSIX and taskkill /T on Windows; platform-specific process-tree behavior still requires Windows integration verification. A detached third-party program can intentionally leave the original process tree and is outside this cancellation guarantee.

Implementation gaps remain explicit: an interactive SSH terminal, interactive extension input and interactive Copilot sessions require a PTY/ConPTY and terminal emulator that are not bundled in the current desktop scope. Native preview prompter also requires a PTY; the visible Material preview is explicitly a local desktop-control preview, not certification of native CLI terminal prompts. The material preview currently covers select, text, password and confirmation controls; native multi-select/search/editor behavior is not reproduced. These are implementation gaps, not claims that Windows cannot implement them. There is no implicit executable installation route.

Genuine runtime blockers include absent GitHub credentials or Codespaces permissions, no active Codespace, remote SSH server missing, SSH/OpenSSH or VS Code launcher unavailable, JupyterLab absent remotely, occupied local ports, unreachable network, extension platform artifacts absent, and a missing or incompatible Copilot executable/account entitlement. These conditions are obtained from local detection or actual CLI failure; no blank disabled page substitutes for the workflow. The app offers refresh and account recovery routes while preserving editable workflow fields. Secondary explanatory text is currently English; domain/action labels have English, Cantonese and bilingual presentation. Complete localized prose and native Windows interactive evidence remain open.
