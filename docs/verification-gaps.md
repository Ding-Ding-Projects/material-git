# Verification gaps

The command catalog describes 196 GitHub CLI leaf commands; 181 definitions are enabled for structured dispatch and 15 require dedicated workflows. These figures describe metadata and dispatch availability. They do not establish successful live execution of every command, flag combination, account state, or Windows workflow.

The desktop application uses official Material Web controls and registered compositions. Source checks and successful compilation do not establish graphical accessibility, component anatomy, narrow-layout behavior, design parity, or genuine built-application interaction. Windows installation, account login, automatic update installation, and end-to-end GitHub operations require their own recorded integration evidence.

The universal feature requirements remain broader than the implemented application:

- The local tools panel includes text/colour/time/unit conversion, an isolated regex workbench, and Ollama model browsing, reviewed pull/copy/delete and bounded non-streaming chat. File/media conversion, an exhaustive model catalog, hardware-fit evidence, durable batch pulls, complete chat sessions, and allowlisted harness launch with rollback remain incomplete.
- Settings provide several persisted presentation and accessibility controls. Scheduled settings, external setting sources, complete section tabs, comprehensive reset controls, and explanations for every setting remain incomplete.
- Command tabs support opening, switching, closing, and unsaved-draft protection. Persistent order, reordering, pinning, grouping, overflow management, four independent discovery searches, and scoped bulk-close flows remain incomplete.
- Localization covers selected application labels. Hardcoded English copy remains, and playfulness currently affects only selected status messages. Three-language coverage and every message category at both playfulness extremes require further implementation and proof.
- Shared presentation-mode state and local TOTP services have implementation groundwork. Full every-element lock interception, factor combinations, timed unlocks, support-ticket recovery, and the unlock ladder remain incomplete. Live cross-application propagation requires integration proof.
- Narration has voice enumeration and serialized platform speech. Full cooldown, superseded-message handling, screen-reader coexistence, actual voice-status disclosure, and unavailable-platform evidence remain incomplete.
- Comprehensive notification history, rendered provider-authored Markdown, offline feature documentation, exports, bulk actions, public product captures, and screen recordings require further implementation or verification.

A completeness claim requires a scoped inventory linking implementation, documentation, localization, persistence, focused tests, negative regression checks, and real built-artifact evidence for each applicable requirement.

Focused subprocess regressions now cover split UTF-8 and credentials crossing an output limit. Bounded regular-file reads are applied before parsing both vocabulary imports and local caches. These checks do not replace a complete privacy or runtime audit.

The public REST/GraphQL schema explorer and reviewed CLI configuration screen are now connected to the desktop. Arbitrary hosts, some request media types, recursive input limits, GraphQL automatic cursor controls, CLI output-transform flags within the dedicated API route, external-code/terminal workflows, and universal feature parity remain incomplete. Account switching, scope refresh, and Git setup have validated service workflows; live browser authorization and native credential mutations have not been exercised in this verification session.
