# 用 Cheap LFS 管理大型檔案

Material Git 可以將檔案內容存放喺 GitHub Release 資產、GHCR 或 Docker Hub，喺 Git 提交細小、帶版本嘅 Cheap LFS 指標。每個指標記錄不可變內容嘅位置、大小同 SHA-256。格式相容 Desktop Material 修訂 `80e0209a12f41df8a6a80ef52925b52ab9ecb1b0`；原生模組附有 MIT 授權同來源。程式唔會安裝或設定 Git LFS，亦唔會設定 Git clean/smudge 過濾器。

開啟已批准嘅儲存庫工作區，再揀「大型檔案」。用「釘選檔案」或者選取清單中嘅路徑，檢查準確操作內容後執行。程式會先上載同驗證內容，再用指標取代檔案。請一齊提交操作回傳嘅指標路徑；私人 OCI 儲存亦需要一齊提交準確嘅儲存庫金鑰。用「還原」驗證同還原原始內容。目的地如果有使用者改動，程式會保留，唔會覆寫。

## 儲存服務

| 服務 | 儲存同憑證 | 限制同處理方式 |
| --- | --- | --- |
| GitHub Releases | 儲存庫所選 GitHub 帳戶；公開讀取可以用匿名連線 | 正常發佈嘅儲存 Release，附準確擁有權標記。新分段上限 500 MiB，每個儲存桶最多 1,000 個資產。舊有 2 GiB 分段仍然可以讀取。 |
| GHCR | 所選 GitHub 帳戶同服務要求嘅套件權限 | 不可變 OCI 清單同分塊，保留歷史參照，驗證來源同套件關聯，以及一致嘅公開／私人狀態。 |
| Docker Hub | 經受保護欄位儲存嘅用戶名稱同存取權杖 | 不可變 OCI 快照，驗證儲存庫政策。實際服務先可以確認方案、配額同權限；有權杖唔代表一定有權操作。 |

OCI 傳輸需要時會取得固定版本 ORAS 1.3.2。執行前會驗證壓縮包、執行檔同授權檔雜湊。固定版本包括 Linux x64、arm64 同 Windows x64；Windows arm64 使用 x64 相容路線。已驗證快取可以離線重用，但傳輸仍然需要連接服務。損壞快取會保留，程式會拒絕執行。

## 暫存、提交同首次發佈

自動釘選會處理所選超過 100 MiB 嘅原始檔案，以及已由 Cheap LFS 管理而有改動嘅檔案。正常 Git 檢查畫面會先列出服務、儲存庫同上載大小。上載失敗嘅檔案會明確排除。部分選取嘅檔案唔可以由整個檔案釘選操作取代。

協調程序會分辨工作目錄內容同已暫存指標。就算已驗證內容已經還原喺工作目錄，新暫存指標仍然會保留喺 Git 索引。如果內容冇改動，而且相同指標已經提交，就會喺今次提交省略。程式會驗證結果索引或提交入面所需嘅私人金鑰同指標位元組。提交鈎子改動咗必要內容會令證明失敗；回退採用 compare-and-swap，保留同時產生嘅新 HEAD。

Release 儲存需要遠端已有嘅提交。用「檢查儲存庫發佈或推送」進入正常發佈檢查。未有 HEAD 嘅新儲存庫需要先檢查同建立初始提交或空白發佈錨點，再推送分支。上載服務唔會虛構遠端錨點，亦唔會用未驗證、本機先有嘅提交上載。

經驗證保留嘅原始副本會喺暫存或提交完成後還原本機內容，失敗或取消準備時亦會嘗試還原。如果同時出現嘅使用者改動阻止還原，該改動會保留，原始副本亦會保留並列出復原位置。復原紀錄只喺本機；如果副本位於作業系統暫存目錄，請喺外部清理移除之前復原。儲存庫更新後嘅自動還原會遵守設定，只處理完整指標。

## 加密同密碼

Release 加密採用固定版本嘅 scrypt 同 AES-256-GCM 容器格式。已儲存密文同還原明文都有完整性證明。開啟加密要輸入兩次相同密碼，並確認冇密碼重設或復原金鑰。指標仍然會公開原始大小同 SHA-256。遺失密碼就無法還原加密內容。

密碼欄位會遮罩。可以只供今次操作使用，亦可以選擇儲存喺原生受保護憑證庫。Docker 權杖使用另一個受保護紀錄，唔會加入一般設定或歷史。私人 OCI 使用不可變快照所需嘅已追蹤儲存庫金鑰；請將金鑰同綁定指標放入同一個已驗證提交。

## 手動上載、壓縮同忽略檔案

手動 Release 上載會準備已驗證本機檔案，開啟準確嘅服務 Release 編輯頁同本機交接資料夾，再檢查服務已接受嘅位元組，先建立指標。呢條路線適用於未加密 Release 檔案。取消後，已接受嘅不可變資產可能會保留供重試。

公開雲端壓縮會準備真正嘅 GitHub Actions 工作流程，包含固定工作程式位元組，供使用者檢查、提交同發佈後執行。歷史指標需要嘅原始資產會保留。私人雲端壓縮目前**不可用**：固定參考版本只提供通過資料洩漏檢查嘅外部建構庫登記要求，冇受支援嘅建立或執行路線。檢查要求唔會開始壓縮、建立建構庫，亦唔會喺私人儲存庫安裝工作流程。

「保留忽略檔案」係本機操作。Git 先證明所選檔案被忽略；程式會複製同計算雜湊，建立本機子模組同初始提交，並喺父儲存庫暫存登記。每個原始檔案都會保留原位。驗證失敗會保留獨立復原副本。呢個步驟唔會建立服務儲存庫或遠端，亦唔會上載或推送。父儲存庫改動要另外檢查。

每個清單同設定子面板都有獨立搜尋狀態同正則表達式建立器。長路徑會換行；傳輸會顯示實際位元組進度、目前同預先下載嘅還原列、排隊數量同取消操作。切換分頁時，密碼同檢查草稿會留喺所屬儲存庫。

## 驗證範圍

目前原生證據包括真實檔案系統同 Git 測試、本機 HTTP 實際位元組傳輸、不可變歷史還原、錯誤密碼保留指標、準確暫存指標保留、compare-and-swap 回退、本機忽略檔案保留，以及官方 Linux ORAS 下載、雜湊驗證同執行。呢啲證明只覆蓋已測試嘅原生行為，唔代表已驗證真實 GitHub／Docker 帳戶權限、配額、組織政策、私人／公開狀態變更、Windows 執行或 Windows 受保護儲存。呢啲測試冇向外部儲存庫發佈檔案。
