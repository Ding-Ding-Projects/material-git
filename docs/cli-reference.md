# GitHub CLI feature and configuration reference

Source: official GitHub CLI **2.102.0**, pinned release at https://github.com/cli/cli/releases/tag/v2.102.0. This inventory is generated by `node scripts/build-cli-reference.mjs` using a clean temporary configuration directory and non-mutating official help calls. `GH_REFERENCE_BINARY` can select the pinned binary; a version mismatch fails. Runtime values and credentials are excluded from the generated artifact.

## Coverage and limits

The built-in catalog contains **196 command leaves**, with **181 structured runner definitions** and **15 explicit adapter exclusions**. These numbers describe catalog coverage, not end-to-end verification of every argument or flag combination. Native aliases that duplicate a command are not additional leaves. User aliases and extension commands are dynamic and cannot be exhaustively inventoried from the built-in binary.

The configuration screen offers **12 of 14 documented keys**: nine enumerated settings and three executable file pickers. API routing and HTTP Unix sockets are unavailable pending reviewed connection adapters. Editor, browser and pager support an executable selected using a native file picker, without arbitrary command arguments or shell expressions. Existing external command strings are hidden. Account credentials and switching remain in Accounts.

## Configuration scopes, overrides and restoration

Global applies to CLI configuration generally. The host selector lists exact hostnames from the native approved-host registry, including approved Enterprise hosts. Global comparisons use the native selected host; explicit host scopes remain independent of the active account. Native `gh config get` returns resolved values with defaults and fallback. Reads use allowlisted keys without a host for Global and with `--host=HOST` for host scope; `config list` defaults to the active authenticated host and cannot accurately represent Global. Clipboard is global-only; telemetry is read globally at runtime in CLI 2.102.0, so both host controls are unavailable. The scope behavior is verified against [the pinned official configuration source](https://github.com/cli/cli/blob/v2.102.0/internal/config/config.go) and [native list implementation](https://github.com/cli/cli/blob/v2.102.0/pkg/cmd/config/list/list.go). These native reads do not distinguish an explicit host value equal to the global value from inheritance, or an explicit global default from an implicit default. The UI reports equal/different values and this ambiguity. It does not claim to show raw storage origins. Environment overrides take precedence where documented; only presence and variable names are visible. Desktop guided commands also force noninteractive prompts and capture their own output.

Changes use native `gh config set` after a scoped before/after review. A stale, expired or no-longer-approved host review fails before a write; a failure after an earlier write is reported as a partial operation. Restore default writes the documented default, including the empty default for editor/browser/pager. It **does not remove the key**. GitHub CLI 2.102.0 has no `config unset` or settings reset command. Removing host overrides to resume inheritance is unavailable without a separate storage adapter. `config clear-cache` clears cached responses, not configuration.

## Capability inventory

- **Built-in commands and flags** (guided): All discovered command leaves and their flags are in the versioned catalog. Catalog-guided means a structured runner definition exists, not that every option combination has interactive proof.
- **Global and host configuration** (guided): Read native CLI-resolved values; review typed setting changes; write with gh config set. Twelve of fourteen keys have controls. Host removal and inherited/default storage origin are not exposed by the CLI.
- **Environment overrides** (reference): Read the official environment reference and the names of active overrides. Values, tokens and credentials are never returned. Editing the parent process environment needs a separate adapter.
- **Help and version flags** (reference): The global --help and --version flags and all help topics are recorded here; command-specific flags remain in the command catalog.
- **JSON, jq and Go templates** (reference): Official formatting topic documents JSON export, jq filters and Go templates. The dedicated API workspace owns its reviewed formatting controls.
- **Command aliases and shell aliases** (adapter-required): Built-in alias commands are inventoried. User-defined aliases can expand to external shell commands, so arbitrary alias execution and import require a dedicated reviewed adapter.
- **Extensions and forwarded arguments** (adapter-required): Extensions run publisher code and can forward arguments to an executable. Dynamic extension commands are outside the built-in inventory and require a reviewed external-code adapter.
- **Interactive terminal, SSH and external applications** (adapter-required): Terminal interfaces, shell completion installation, arbitrary editor/browser/pager arguments, SSH, Copilot and extension execution require their own adapters. No shell command entry is offered.
- **Accounts and credentials** (guided): The Accounts screen owns device sign-in and account switching. Token export and terminal authentication output do not belong in the configuration screen.
- **CLI response cache** (reference): gh config clear-cache clears cached CLI responses. It is a separate command in the catalog and does not reset settings.
- **Terminal accessibility** (reference): Official accessibility help covers accessible colors, accessible prompting and spinner behavior. Desktop appearance and accessibility preferences are separate.
- **Telemetry and diagnostics** (reference): Telemetry and debug environment behavior are documented. The setting is guided; exposing debug output and changing environment values require a separate reviewed workflow.

Aliases can interpolate positional arguments and shell aliases can execute arbitrary shell commands. Extensions execute external publisher code; installed extensions cannot override core commands, and `extension exec` can select a conflicting name. Those behaviors are documented from official help and require adapters. Generated shell completion scripts are inventory features; installation into a user shell profile is not implemented here. Experimental and preview features retain their official status; a help entry is not proof that the current account, platform or server supports it.
