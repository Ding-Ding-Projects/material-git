# GitHub API explorer

The GitHub API route builds guided forms from the vendored official REST OpenAPI and GraphQL schema. Catalogue counts describe metadata coverage. They do not prove that every endpoint works with every account, enterprise version, permission, or media type.

Search REST operations by resource or summary, select a category, then choose an operation. Catalogue pages contain 25 operations. Text search covers the full catalogue; regex and method filters cover the currently loaded page. The search uses the existing bounded regex worker and adjacent regex builder.

Path parameters, query parameters, request headers, and request body have separate sections. Every parameter keeps its provider description, type, required label, and available default. Operation, parameter, body, GraphQL field/type, and deprecation descriptions use the shared registered `mg-api-markdown` composition. It parses Markdown with the existing `marked` dependency, sanitizes with `DOMPurify`, and permits only text document structure such as paragraphs, headings, lists, quotes, code, tables, and links. Scripts, styles, frames, objects, external images, inline event handlers, and arbitrary attributes are removed. Only absolute HTTPS links without URL credentials remain clickable. Link activation prevents browser navigation and uses `window.material.openExternal`; middle clicks take the same route, and link context menus cannot bypass it. Keyboard activation remains native link behavior with visible focus. Link failures show a persistent local message. Input is capped at 32,768 characters. If sanitized markup exceeds 2,048 elements, safe plain text replaces the rich structure. Parsing failure shows escaped text. Truncated input and the element-limit fallback show an honest limit notice. Optional controls distinguish omission from a deliberate value of `false`, `0`, an empty list, or `null`. Boolean values use switches, enums use searchable Material selects, numbers use fields and increment controls, lists use removable chips and typed item controls, and objects expose property fields on demand. Schema alternatives have a shape picker. Nested local references and `allOf` composition are resolved without eagerly expanding recursive objects. Provider patterns are shown as help; their exact matching remains server-authoritative. Renderer and main-process checks do not prove pattern conformance.

Natural text such as descriptions and message bodies uses text areas. The request is assembled from typed values; a raw JSON request editor is not required. The read-only request preview redacts credential-like keys and recognizable GitHub token shapes. Binary uploads use a native picker and an opaque main-process file grant, limited to 64 MiB. The renderer receives filename and size, and never the selected filesystem path. Grant handles are replaced by file descriptions in previews. Authentication uses the active GitHub CLI account; sensitive or undeclared authentication headers cannot be entered through this form.

GraphQL uses a field tree starting at the schema's query or mutation root. Each selected field exposes its description, output type, optional alias, typed arguments, and nested output fields. Field pages contain 12 items and have their own search and regex builder. Interfaces and unions expose selectable type fragments. The main process validates the complete selection and generates the document. The generated document is a read-only preview, rather than the sole editing interface. Query and mutation drafts remain separate.

Every mutation opens a review identifying the operation and request. Sending requires two independently operated acknowledgements, moving the authorization slider to 100, then pressing Confirm and send. The slider stays disabled until both acknowledgements are checked. Changing either acknowledgement resets it. Emergency exit and Escape cancel the review. Changing fields also cancels authorization. The submitting handler refuses a second request while one is active. These controls supplement the main process confirmation boundary.

Responses show HTTP status, success or failure, endpoint, actual returned data, optional headers, and truncation. GraphQL errors are failures even when HTTP status is 200. A partial-data marker identifies a GraphQL error envelope that also contains returned data; both remain inspectable. Structured arrays provide a table of up to eight columns plus each complete record; nested values use expandable trees. Result pages contain 20 local records. Load next server page follows only the link returned by the backend. JSON and CSV exports use the native export bridge. Binary download responses report the actual native export outcome. Request errors persist until dismissed.

REST and GraphQL drafts survive route remounts for the current application session. They are never written to browser storage. Results are instance-local, and a request completing after its originating component disconnects cannot paint a completed result in a new instance. The component emits a composed `api-work-state` event with `{busy, dirty}` for host leave and close guards; completion after disconnection emits the same event on `window`. The host must consume that event to enforce its own navigation decisions. A session-wide count keeps `busy` true while any request remains active, including one whose originating component has disconnected. A remounted explorer cannot submit another request until that work finishes, and its instance-local result remains empty.

Discard current draft resets the selected REST operation or GraphQL mode. Discard all session drafts resets every stored REST and GraphQL draft. Edited drafts first require an explicit discard review, which identifies the current operation or affected draft count and explains that no API call will be sent. Keep drafts or Escape cancels that review. Confirming restores schema defaults and removes the corresponding dirty state; clearing all edited drafts emits `dirty: false`, allowing host close and updater guards to clear. Both discard controls stay disabled while requests are active. Drafts containing secrets disappear when discarded or when the process exits.

## Component provenance

`mg-api-explorer`, `mg-api-field`, `mg-graphql-tree`, `mg-api-records`, and `mg-api-markdown` are registered Lit compositions. The Markdown composition owns its sanitized document elements inside its shadow root, including accessible HTTPS anchors; it does not inject provider HTML into the application shell. Their internal structure, typography, disclosure, record tables, and response trees use inherited Material Design 3 surface, color, shape, and type tokens. Interactive controls are the genuine registered components from `@material/web` 2.5.0: buttons, switches, checkboxes, select options, chips, tabs, text fields, sliders, and progress. Protocol navigation uses genuine `md-tabs` and `md-primary-tab`, with explicit accessible labels. Selected options provide their initial labels for category, body content type, schema alternatives, and enums. `mg-search` is the existing registered regex composition. The explorer owns a shadow stylesheet; the shell's `mg-scroll` contains its natural-height document. Bounded lists and previews have tokenized native scrollbar fallbacks. No main-process, shared bridge, shell, or global stylesheet is owned by this renderer change.

English, Hong Kong Cantonese, and bilingual interface labels follow the supplied settings; School mode selects English. Official provider descriptions and operation names retain their original wording. Controls expose accessible labels and keyboard behavior. REST/GraphQL tabs have selected states and arrow navigation, destructive review supports Escape and keyboard slider input, and reduced-motion styles remove the authorization transition.

## Verification and remaining limits

Run `node --import tsx --test tests/api-form.test.ts` and `node tests/api-controls.browser.mjs` for the focused checks. The browser check uses an isolated temporary directory and Chromium profile, and removes its temporary files. Set `MATERIAL_GIT_CHROMIUM` to an installed browser when required.

Focused pure tests cover defaults, omission, nested references, required values, composition, ranges, enums, null, and preview redaction. An isolated Chromium component test with a clearly labeled transport fixture verifies typed GET assembly, preserved drafts, a gate that stays disabled with zero or one acknowledgement or an unfinished slider, keyboard slider completion, cancellation without sending a mutation, a 420-pixel layout without overflow or page errors, unspecified JSON type selection, lazy repeated recursive inputs, actual fixture cursor advancement, and browsing enum documentation, accessible tab labels and arrow/Home focus, initial category and content-type labels, reviewed discard cancellation and reset, clearing all dirty state, and a deferred request remaining busy across remount without painting a stale response. Malicious Markdown checks verify rich heading/quote/emphasis structure, removal of scripts/styles/frames/images/event handlers and unsafe link schemes or URL credentials, HTTPS bridge activation without page navigation, zero external resource requests, and a visible input-limit notice. That fixture is component evidence, not a live GitHub call or installed application proof.

Live read-only verification after host integration can select REST `GET /meta` (`meta/get`) and press Send request, then select GraphQL `viewer`, select `login` below it, and press Run query. Confirm the actual HTTP status and returned records. Do not send a mutation while testing the gate. The host owns the real read-only API verification record.

Cookie request parameters are unavailable in the backend. The bridge supports declared JSON and text bodies, plus the declared binary release-upload body; the pinned catalogue declares no multipart or URL-encoded form request media types. Recursive GraphQL inputs expand one object level on demand, including repeated types, with a visible 16-level editing limit. They retain typed property controls. Unspecified JSON values and additional properties use a type picker for text, finite number, boolean, object, list, or explicit null. REST reference descriptions may be bounded by backend limits, with unresolved references explicitly unavailable. Complex schema keywords beyond the implemented typed controls still require backend validation and additional operation-specific verification. GraphQL forward connection pagination adds schema-defined page information and offers a next-page button based on actual returned cursors. Partial responses, multiple advancing connections, and connections repeated under arrays do not advance automatically. Full per-surface settings/search localization, persistent app-wide notification history, and universal feature inventory proof remain integration obligations. Windows installation and live mutation success/failure are unverified by this renderer change.

## Type browsing and request options

Browse all GraphQL types opens a searchable catalogue of all 1,829 named types with 25 types per page and a kind selector. It includes objects, interfaces, unions, input objects, enums, and scalars. Selecting a type shows its provider description; field, input, and enum members have their own search and 12-member pages, and output fields show scoped argument documentation. Enum argument controls show the selected choice's description. Browsing a type does not execute a request or edit the selection tree.

Response format, API version and cache opens Material selectors for the declared Accept formats, host default or REST version `2022-11-28`, and read caching. The response field view selects one actual returned field without requiring jq syntax; JSON and CSV exports follow that view. The host selector lists only registrations approved elsewhere in the application. Changing hosts clears the result and cancels a pending review. Permissions and schema differences remain authoritative at the host.
