# GitHub CLI command coverage

The checked-in catalog is generated from the checksum-verified official GitHub CLI 2.102.0 Linux AMD64 release. It contains all 196 canonical leaf commands exposed by recursive `gh help` discovery. Built-in aliases and help topics are not separate commands. The generation script fails if the binary version changes or any help lookup fails. Download checksums for supported Linux, macOS, and Windows x64/ARM64 archives are pinned in `scripts/fetch-gh.mjs`.

The catalog has 181 command definitions available to the guided runner and 15 requiring a dedicated authentication or external-code workflow. These counts describe dispatch availability, not completed live verification or every possible flag combination. All 196 canonical commands remain inspectable. Safe noninteractive listing, search, skill preview, run watching, completion generation, and local git operations are available. Browser navigation uses `browse --no-browser` and returns the destination URL. Native cloning, checkout, sync, PR creation/revert, and issue development require explicit mutation review and a workspace approved by the main process; they can invoke Git and its trusted local configuration.

The 15 generic runner exclusions are authentication login/refresh/setup-git/token; Codespaces SSH/VS Code/Jupyter; shell-oriented alias import; Copilot; extension browse/create/exec/install/upgrade; and preview prompter. The dedicated account workflow implements real device login, status, verified account switching, reviewed permission refresh, verified Git credential-helper setup, and local logout, keeping authentication output out of operation history. Token export is unavailable. Browser/editor flags, external diff, shell aliases, arbitrary git passthrough, and external-helper/transport configuration changes remain rejected. Extension list/search/remove and ordinary non-shell alias management are available.

Available commands use structured flags and positional arguments with no shell. Unknown names, invalid types, unsupported enum values, null bytes, excessive values, and working directory escapes are rejected. Flags use `--name=value`; positional values follow `--`, preventing values from becoming flags. API requests require confirmation, a relative endpoint, github.com hosting, and managed authentication headers. Every catalog command classified as a mutation requires explicit review confirmation; this conservative classification also includes local downloads.

Help describes most flag types and enums, but does not encode all command-specific relationships, dynamically configured choices, default prompt requirements, or GitHub API constraints. Such errors are reported by the real CLI; no successful result is synthesized. Optional positional alternatives such as number/URL/branch remain flexible typed text/entity inputs. Help-provided JSON fields receive multiple-choice controls. Remote entity pickers and Windows GUI behavior require separate integration verification.

Execution closes stdin, disables prompts, uses a five minute timeout, bounds retained output to one MiB per stream, supports cancellation, and publishes operation snapshots. Token patterns and supplied secret values are removed from displayed output. A UTF-8 decoder preserves characters split across process chunks. Streaming redaction keeps undecided secret suffixes and removes recognized GitHub token patterns before applying the one MiB byte cap, preventing a cutoff from exposing a credential prefix. Known partial secret suffixes of at least four characters are suppressed on stream completion. Unknown credentials without recognizable GitHub token patterns cannot be identified automatically. Output limits bound retained buffers, not remote command work. Cancellation terminates the direct CLI process; descendant process-tree termination is not implemented. No mutating GitHub commands are used in tests. Local unit tests check validation and process lifecycle; they do not establish live GitHub or Windows interactive parity.

## Dedicated account authentication

`AuthService` executes pinned CLI `auth login --web --git-protocol=https` with an exact allowlisted hostname and selected supported scopes. Noninteractive CLI prints a device URL instead of opening a browser; the account panel opens that validated URL only when the user presses its browser button. One-time codes are transient authentication state and are cleared on completion or cancellation. Raw authentication output is never forwarded to normal operation streams. Status reads `auth status --json hosts` and exposes a whitelist of account metadata, excluding both token and token error fields.

GitHub CLI manages credential storage and may fall back to its configuration file if no system credential store is available. The panel reports the credential source. Local logout removes the local account; it does not revoke the token on GitHub. Environment-token accounts cannot be switched or removed by this workflow. Enterprise hosts require an explicit constructor allowlist; arbitrary hostname entry is unavailable. Injected-process tests verify validation, transient code cleanup, URL restrictions, status filtering, and reviewed account changes. They do not establish a completed browser login or credential storage behavior on Windows. The main process approves native workspace folders before constructing the runner. Local git operations are enabled only within that approved workspace and require explicit mutation review. The CLI may honor Git hooks or helpers configured in that trusted workspace.

## Structured command constraints

Issue and pull-request creation, including revert creation, require a title and body (or body file) rather than an interactive editor. Clone history depth, branch, and single-branch behavior use guided controls translated to known Git arguments; raw git flags are rejected, and clone destinations must remain inside the approved workspace. An explicit command repository overrides the global repository context. Config keys are enumerated; safe configuration values are checked against their key. The dedicated CLI configuration panel selects external helper executables through a native picker; additional command arguments, API host overrides, and Unix socket overrides remain unavailable. Completion shell and API method use enumerated choices. Integer controls have finite bounds; zero is rejected for pagination limits, intervals, ports, and clone depth.

API field and raw-field controls repeat structured name=value entries, and headers repeat name: value entries. Authentication/Host overrides are rejected. API field type conversion follows the official CLI semantics; scalar and array notation is visible in the field descriptions. All API requests require review because fields and method can change the HTTP operation. Argument alternatives are grouped as one control; optional owner/repository/entity arguments use picker metadata when the main process provides a source. Server-dependent enum values and every mutual-exclusion relationship are not encoded, and the CLI reports such failures honestly.

## Dedicated API and configuration routes

The `api` catalog entry opens the schema-based REST/GraphQL explorer; config entries open the reviewed CLI settings screen. Those dedicated routes are not equivalents for every raw `gh api` flag, output template, custom host, or experimental transport. API schema metadata covers the pinned public GitHub.com sources; see [API coverage](api-coverage.md) and [GUI limits](api-explorer.md). Generic-runner counts remain separate from dedicated adapters and live command verification.
