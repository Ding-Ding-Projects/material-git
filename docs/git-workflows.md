# Native Git workspace

Material Git has a dedicated Source Control workspace backed by the selected native Git executable. It opens repository folders through the native picker and retains opaque grants in the main process. Renderer requests contain task fields, never executable paths, shell input, command fragments or arbitrary working directories.

The Changes destination shows the index and working files separately, plus untracked files. Whole-file and individual text-hunk staging use the real Git index. Commit, amend, optional author override and signing each receive an exact review. Binary, added, deleted and renamed files use whole-file staging. Untracked files are preserved by Discard. Symlink files and filenames containing line breaks currently require another filesystem workflow.

History contains a commit ancestry graph generated from actual parent object IDs, full commit patches, file history, blame, notes, cherry-pick, revert and reviewed reset modes. Native filters select references, all references, merge commits, first-parent traversal, ordering, literal author names, UTC date ranges and literal or PCRE commit-message search. File history can follow renames. Search uses the adjacent regex builder; its JavaScript preview and native Git PCRE matching are identified separately, and unsupported builder flags are rejected. NUL-framed records preserve tabs in commit subjects and author names. Graph edges outside a page continue below it. Branch actions create, switch, rename, merge, rebase and delete merged branches. Git protects occupied branches and dirty working files.

Remotes supports explicit fetch, pull strategy, single-reference push, remote add, rename, URL change and removal. Push never adds force. Account identity follows the selected remote URL and trusted credential helper configuration. No remote mutation is performed by the test suite.

Tags and stashes support creation, signing, deletion, saving, apply, pop and drop. Working trees supports native-picked addition, lock, unlock, clean removal and pruning missing registration entries. Submodules supports add, initialize/update, sync and deinitialize with selected recursive behavior.

Conflicts shows the base, current and incoming versions next to an editable resolution. A reviewed resolution atomically replaces the selected file and stages it. Merge, rebase, cherry-pick, revert and mailbox import can continue or abort; eligible operations can skip. Recognized credentials in a conflict refuse this editor rather than silently replacing them with redacted text. Resolve those files in a protected editor, then stage them.

Patches imports native-picked patch bytes, applies or reverses them in the worktree or index, imports mailbox commits, and exports a selected number of commit patches into a fresh directory. Sparse checkout has selected directory cones and disable controls. Shallow clones and deepen operations are supported; partial clone uses blob-on-demand filtering.

Repository Settings displays every stored key with its scope and origin, including included configuration. Search is adjacent to the application's regex builder. Arbitrary valid section.key names can be reviewed for set/unset at local, enabled worktree or explicitly selected global scope. Secret keys cannot be written through this ordinary editor, and existing secret values are masked. Worktree scope refuses a silent local fallback when extensions.worktreeConfig is disabled. Executable aliases, named hooks, filters, merge/diff programs, credential helpers, SSH programs, signing tools and include directives are marked for inspection. This interface does not execute aliases.

Repository subtrees can add, merge, pull, split and publish selected directory history. A second native picker can approve a local source repository without changing the active workspace; its opaque grant and current state are bound into the review. Local repository access is permitted only for that approved plan. Git subtree push branch names are normalized to avoid an unintended refs/heads/refs/heads namespace, and no force refspec is accepted.

Advanced workflows include note append/copy/merge/prune with an editable notes-conflict recovery path; stash recovery onto a branch; explicit upstream tracking; detached commit inspection; sparse add/reapply; linked working tree move/repair; submodule metadata absorption and tracking/URL changes; commit/tag signature verification using a disclosed signing program; tracked-file rename, removal, revision restoration and index properties; bundle import/export/reference fetch; revision archives; selected untracked file cleanup; exact recovery entry deletion; and reviewed object packing, graph/index rebuilds and pruning. Destructive choices are explicit and receive single-use review. Bundles are copied into owned immutable input storage before use.

Object storage additionally creates trees through typed name/type/object entry rows, including executable files, symbolic-link contents, subdirectories and gitlinks. Reviewed two-ref integration previews store merged trees and conflict blobs without moving HEAD or replacing the index; the result reports conflicts and whether reviewed state stayed unchanged. Configured merge drivers require explicit program trust. It stores exact native-picked binary bytes as blobs, creates trees from the index, and creates unsigned detached commit or tag objects with typed parents and identity fields. Index tools load or merge one to three selected trees, explicitly empty the index, assign a validated regular-file blob entry, and restore staged contents to a selected working file with a separate overwrite choice. These object creation tasks return object IDs without moving a branch; callers must retain those IDs before pruning.

Maintenance includes real index, reference, recovery log, object storage, integrity, attribute, ignore and blame inspectors. Attribution renders source lines with their real commit and author, supports bounded line pages, and optionally ignores whitespace or detects moved/copied lines. Recovery entries retain their actual selector and object ID, with literal message filtering and paging. Tracked-content search independently selects working files, index contents or a revision, using literal/PCRE matching, optional case folding and bounded context lines. External text conversion is disabled and binary files are excluded. Regression search additionally supports skip, standard journal replay, native terms/log inspection, first-parent or file-scoped candidates, custom positive/negative terms and no-checkout mode. The actual BISECT_HEAD candidate is surfaced and classification uses that candidate rather than silently marking unchanged HEAD. Replay rejects scripts and unsupported log options. Reviewed actions run object maintenance, reference packing, recovery expiration, bisect start/good/bad/reset, notes, object replacements and compare-and-swap reference updates.

## Native safety and recovery

Writes use single-use reviews that expire after five minutes. Reviewed file input is limited to 64 MiB per changed file and 128 MiB in aggregate, with complete bytes hashed within those limits. Their native plan is bound to HEAD, index, working files, operation state and configuration fingerprints. A changed state invalidates the review before mutation. New repository reviews bind the native-picked parent and require an unoccupied destination. Exports require a new output directory.

All subprocesses use separate argument arrays with shell disabled. Filename arguments follow the end-of-options separator where supported. Paths are relative to an approved native root; traversal, metadata directory access and escaping symlinks are rejected. Reads disable external diff, textconv, filesystem monitors and automatic maintenance. Untrusted writes disable directory hooks and credential helpers and reject external/custom transport protocols. Remote operations never silently push submodule references. Configured filters or named hooks require explicit repository program trust for tasks that can execute them. Trust resets when another repository is opened. Signing also requires this disclosure.

The main process caps output at 2 MiB and kills the owned process group on cancellation or timeout. Read requests use UUIDs bound to active native requests; numeric process IDs and unknown requests cannot cancel unrelated processes. Cancellation stops later reads in the same snapshot pipeline. The GUI exposes cancellation during inspections as well as reviewed writes, and cancelled writes refresh actual state. Cancellation and nonzero exits report possible partial effects, and the GUI refreshes actual repository state. The application must retain its quit/update guard while a Git request or draft review remains active. GitService.close() cancels owned subprocesses and removes its owned temporary hook directory.

## Verified behavior and remaining scope

The native fixture suite isolates Git configuration and creates owned temporary repositories. It verifies staging and unstaging preserve independent contents, selected-hunk staging, stale and single-use receipts, symlink/path boundaries, directory hook suppression, included executable configuration disclosure, secret masking and fingerprint invalidation, actual branch/tag/stash arguments, real merge conflict editing and continuation, actual process-group cancellation, reviewed initialization patch export, alias-help rejection, full content fingerprints above display limits, bare repository inspection, and browser interactions that stage/unstage through the real native service and render the ancestry graph. The extended fixtures also verify notes conflict completion, sparse cone extension, native-picked linked tree movement, actual ZIP and bundle import/export, isolated real signing keys and signature trust results, submodule metadata/branch/URL changes, tracked file restoration, explicit deletion, index flags and real object packing/graph maintenance. TypeScript checks the native and renderer contracts.

These checks do not establish Windows installer interaction, bundled Git execution, live remote authentication, recursive submodule network behavior, every maintenance variant or the complete Git CLI. The audit in `coverage/git-actions-audit.md` is the authoritative exhaustive inventory and distinguishes implemented evidence from pending coverage.

The workspace currently exposes 121 reviewed task identifiers, 42 repository inspectors and the core inspection actions. That is task coverage, not a claim that all 173 audited Git entries or all documented options have a GUI. Remaining groups include interactive rebase todo editing and sequencer scripting, replay/history experimental tools, gitk/gui and interactive terminal-only tools, daemon/server protocols, mail-send credentials, arbitrary filter drivers, custom merge tools, additional low-level object creation/index batch pipelines, additional bundle/archive variants, credential-store editing, full bisect command automation, every merge strategy option, full reflog/reference transaction batching, multi-path restore variants, scripted submodule foreach, and version-specific options introduced after the available runtime.

The renderer is a registered Material Web/Lit composition and uses shared theme tokens, narrow layouts, reduced-motion rules, keyboard controls, bounded list pages and custom scrollbar styling. Native Git output and repository-owned data retain their original factual wording. English and Cantonese navigation, primary actions, task descriptions and editor field labels are provided. Native diagnostics and ancillary explanatory copy retain literal English where no reviewed translation is present.

# 原生 Git 工作區

版本管理工作區會用原生檔案選擇器開啟儲存庫，實際讀取 Git 暫存區、工作目錄、分支同提交歷史。每個寫入操作都要先檢查，確認會綁定當時嘅 HEAD、暫存區、檔案同設定。狀態改變會令確認失效，取消或者操作出錯之後會重新讀取真實狀態。

介面提供分開嘅已暫存、未暫存同未追蹤清單、逐段暫存、提交、分支、遠端、標籤、暫存、工作目錄、子模組、修補檔、衝突解決同維護工具。衝突編輯器並排顯示共同版本、目前版本同傳入版本，再用確認後嘅內容解決。程式信任會喺開啟另一個儲存庫時重設。

目前測試用隔離嘅臨時儲存庫確認原生 Git 行為，唔會改動用戶遠端。完整 CLI、每個選項、Windows 安裝互動同未驗證嘅網絡工作流程仍然要按覆蓋報告逐項完成，唔會因為有操作名稱就當作全部完成。

Remote cards group fetch/push URLs under one configured name. Advertised-reference controls read branches, tags and symbolic HEAD with typed scope and name-prefix filters. Native process output is bounded; visible pages show 100 references. Repository-program trust is explicit, and default trust blocks local/custom protocols. Selecting an advertised branch seeds an explicit source-to-tracking-reference fetch that still requires native review before applying. Real owned local fixtures prove read preservation, protocol rejection and the browser-selected reviewed fetch.

遠端卡會將同名擷取同推送網址集中顯示。遠端參照介面支援分支、標籤同符號 HEAD，只讀操作唔會更改遠端。選擇分支之後仍要檢查原生確認，先至可以擷取到明確追蹤參照；真實臨時儲存庫測試已驗證呢個流程。

Dedicated reference/index inspections validate full reference or branch names through native Git, compare selected branch tips or bounded ancestry, and display explicitly selected resolved identities/settings without launching configured programs. Difference controls compare index versus working files or a chosen tree versus index/working files, with independent source selection and stat/name/raw/patch presentations. Real fixtures verify preservation of independent staged and unstaged contents; the app browser verifies native valid/invalid reference feedback.

專用參照同索引工具會交由 Git 檢查名稱、比較所選分支，或者顯示明確選擇嘅身份設定，唔會執行編輯器。差異控制分開比較索引同工作檔案，或者指定樹同索引／工作檔案，真實測試確認暫存同未暫存內容各自保留。

Three-file merging uses three opaque native-picker grants and copies verified UTF-8 input bytes into owned temporary files. Git merge-file writes only its preview output; originals, HEAD and independent index/working changes remain unchanged. Controls select conflict style, favor policy, algorithm and marker length. Conflict counts cap at127 and display127+ when capped. The editable result saves only through an expiring, single-use native review and a fresh filename in a native-picked output directory. Existing paths, changed source inputs, metadata directories and recognized credentials are rejected; unresolved markers require explicit acknowledgment. No user-file snapshots are persisted. A real browser fixture picks all three inputs, previews a conflict, edits the result and saves a fresh file while preserving original bytes and index.

三個檔案合併只用原生選擇器批准嘅來源，同已核對文字暫存副本。原本檔案、HEAD、索引同工作變更都會保留。結果可編輯，但要經限時一次性原生確認，另存到原生選擇目錄嘅新檔案；唔會覆寫現有檔案，來源變更亦會拒絕。未解決標記要明確確認，唔會永久保存用戶檔案快照。

Provider-selected repository/gist cloning carries only an opaque native source ID from the renderer. Main resolves the approved host/account/provider identity and fixed HTTPS URL at review and again before Apply; renderer replacement URLs and configured URL rewriting are rejected, and automatic HTTP redirects are disabled. Existing directory/receipt staleness guards still apply. Provider completion accounting runs only after a native mutation attempt and reports an accounting failure without claiming rollback. Actual owned HTTPS fixtures prove Git cloning and pre-mutation source/relock/discard rejection; they do not prove live authenticated GitHub transport. Provider-selected pull-request checkout requires a native-approved clean local repository with a matching base-repository remote. It fetches into a fresh owned reference without updating FETCH_HEAD, verifies the exact approved commit, rechecks local state and provider authority, then creates and switches to a fresh non-forced branch. Ignored-file collisions are preserved. Cleanup deletes only the temporary reference still holding the reviewed SHA; mismatches remain explicitly reported. Actual HTTPS fixtures cover success, relocked permissions, head mismatch, staged/working/untracked and ignored preservation, changes during fetch, and owned fetch cancellation. Downloaded objects and possible temporary references are reported honestly after cancellation or failure. The public asynchronous workspace discard method refuses active work, revokes its unused native review and clears draft state without modifying repository files.

來源合併請求檢出要先用原生選擇器批准乾淨本機儲存庫，同時核對遠端身份。程式擷取到專用暫存參照，核對確實提交，再次檢查本機狀態同來源權限，先建立同切換新分支；唔會強制切換或者覆寫忽略檔案。取消同失敗會如實報告下載物件或剩低參照，清理只刪除仍然符合已確認提交嘅專用參照。

Embedded selected-provider tasks use compact contextual controls until the operation returns its actual local snapshot. Repository clone branch choices are supplied as paged native provider rows through `providerBranchChoices` (branch names, current page, next-page state and busy state); `provider-branch-page` carries typed page/query events. Choosing a branch preserves the edited folder and checkout options. Gists and pull-request checkout omit the repository branch picker. Compiled Material interaction verifies keyboard selection, query/page events, hidden source URL and unrelated controls, plus awaited draft cleanup. Native provider branch responses and actual HTTPS Git outcomes retain separate evidence.

Conflict reuse controls inspect the recorded cache, active paths, remaining conflicts and resolution differences. Reviewed actions record or replay resolutions, forget one current conflict, clear unresolved records, or remove old variants with typed retention days. `rerere.autoupdate` is explicitly disabled, so reused working contents require separate inspection/staging. Read controls avoid creating a missing cache. The exact native metadata locations, every cache variant byte/mtime and the active journal are bound to review, with link, size and path checks. Real repeated-conflict fixtures and compiled Material interactions verify native recording/reuse and independent index/working preservation. Full per-option and per-form GUI evidence remains open.

衝突重用介面可檢查已記錄快取、目前路徑、剩低衝突同解決差異。記錄或重用、忘記所選衝突、清除未解決記錄同按日數清理舊版本都要原生確認。自動更新索引明確停用，重用內容要另行檢查同暫存。原生快取位置、所有版本內容及時間同目前記錄都綁定確認，連結、大小同越界路徑會拒絕；真實重複合併同 Material 控制測試確認索引同工作內容各自保留。

Message metadata controls call native `interpret-trailers` with structured key/value rows, insertion/duplicate/missing policies, empty-value trimming and existing-trailer parsing. Inputs stay in memory and output stays a preview; no in-place file editing occurs. A successful full-message preview can seed the ordinary reviewed commit editor. Parsing ignores configured trailer commands, while editing with them requires explicit program trust and exposes those settings in the repository disclosure. Drafts containing recognized credentials are rejected instead of silently applying masked text.

Pull-request prose controls call native `request-pull` using a configured public remote or an opaque native-approved local source, resolved starting/ending commits, optional advertised reference and patch output. The command reads refs and generates prose; it does not push, send mail or create a GitHub pull request. An unadvertised head remains a failed verification with the generated text and explicit native warning. Configured external diff programs require trust. Cancellation kills the owned script group and reports possible external-program effects. Source changes during generation are rejected. Message/pull drafts emit dirty state and require explicit clearing before switching draft tools; abandoning a parent draft awaits the same cleanup contract. Real fixtures and compiled Material controls prove preview-to-commit seeding, native selected-source generation, actual trailer-program trust boundaries, unchanged independent index/working contents, unpublished-head warnings and cancellation. Live authenticated transport and Windows script execution remain separate unproved evidence.

訊息資料介面用結構化鍵值、位置、重複或缺少政策同純解析去呼叫原生尾段工具，只產生預覽，唔會原地改檔案。完整預覽可填入另行確認嘅提交編輯器。解析唔會執行設定尾段程式；編輯時要明確信任，認得嘅憑證會拒絕，唔會靜靜提交遮罩文字。

拉取請求文字用設定遠端或原生批准本機来源、確實提交範圍同可選修補內容產生，只讀參照，唔會推送、寄信或建立 GitHub 合併請求。未發佈提交保留原生警告；外部差異程式要信任。取消會終止專用程序組並如實報告可能副作用，草稿會發出未儲存狀態，切換工具前要明確清除。


Object pack tools select standalone pack or index files through the native file picker. Inputs have a 128 MiB limit, one-million-object header/fanout limit and complete byte fingerprints. Binary index inspections validate native SHA-1/SHA-256 format, fanout, table length and checksum before displaying paged object IDs, offsets and CRCs. Pack verification creates and indexes copies in owned temporary storage, then runs actual verification; summary display runs verification before the statistics-only call. Inputs and repository objects, refs, index and working contents remain unchanged. `index-pack` does not accept an end-of-options separator in its file form; those arguments are exclusively native-generated absolute temporary paths.

Reviewed standalone object import pins the input checksum, repository state, guarded pack-storage metadata and every content-addressed destination. Matching existing pack/index/retention-related destinations reject the import. Apply creates a new pack, index and persistent keep marker with native strict object checking. It does not move references, stage files or replace working contents. Thin-pack repair and overwrite modes are not exposed. A failed or cancelled import can leave imported objects or a keep marker, so its result reports possible partial storage effects rather than rollback. Real SHA-1/SHA-256 fixtures verify inspections, actual imported object contents, stale sources, changed destinations, invalid checksums/fanout and metadata links. Compiled Material interaction chooses both native inputs, verifies, inspects, reviews and imports through the actual service. Windows execution and complete command/option coverage remain separate unproved evidence.

物件封裝工具用原生選擇器批准獨立封裝或索引，限制輸入大小同物件數量，綁定完整內容。索引會先核對原生物件格式、表長度同校驗值，再分頁顯示物件、偏移同 CRC。封裝檢查只用專用暫存副本；摘要模式亦會先實際驗證，來源、參照、索引同工作內容都保留。

匯入要限時一次性原生確認，綁定來源、儲存庫狀態、封裝儲存資料同所有新目標，同名現有檔案會拒絕。操作只建立新封裝、索引同持久保留標記，唔會移動參照、暫存或改工作檔案，亦未提供精簡封裝修復或覆寫。失敗或取消可能留下物件或保留標記，結果會如實報告。真實 SHA-1、SHA-256 同 Material 測試證明所述流程，Windows 同全部選項仍要另行驗證。
