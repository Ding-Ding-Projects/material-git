# Records, history and activity

The history workspace combines validated workspace snapshots with the native managed revisions already recorded for settings, schedules, appearance and other supported local records. The isolated local Git repository belongs to application data; it never changes a user repository. Revision labels and retained counts use the native record APIs. Comparing managed revisions requires the same source kind and record identity, and shows complete sanitized field differences. Browsing, comparison and export do not restore a record.

Text and full regex searches compose with inclusive dates, actual recorded actions and actual source kinds. Counts come from the records returned by the native store. The bounded calendar opens beside the date fields and supports searched months, year jumps, range selection, arrow-key day movement and presets. Local dates and `YYYY-MM-DD` are accepted; unfinished, impossible or reversed typed ranges remain visible while the last valid filter stays active. Dates use the device's local timezone. Each collection and choice list owns independent search state and its adjacent regex builder.

Twenty rows appear per page. Page selection accumulates across pages; matching-set selection, inverse selection, clear selection, Shift-click and Shift+Space have explicit scopes. Hidden selections remain selected but are excluded from the filtered action/export set. A selection with no current matches exports nothing. The formats derive from the exact datum: record arrays support JSON, JSONL, YAML, XML, CSV, TSV, HTML, SQL text, Markdown and text. Scalar or whole-workspace data expose only faithful formats. Serializer disclosures appear before the native save dialog. Full importable backups retain the reviewed version 1 JSON envelope independently of the table-format choice.

Restoring workspace, settings or schedules requires the exact snapshot review, two acknowledgements and a confirmation slider. The existing native handler validates the record again and appends a revision. Other managed kinds are explicitly audit-only here; this panel does not claim to restore credentials, security records or external provider state. Workspace and managed-history pruning are separately reviewed, show the actual retained/removed counts and use the bounded native APIs. Import validates a complete local JSON envelope and reviews replacement before applying it. Table exports and managed-history exports are read-only audit data.

The activity workspace filters active-session operations by command/status/output search, inclusive dates and actual statuses. It paginates and selects the same way as records. Its metadata export excludes command inputs, credentials and session output; visible standard/error output can be exported explicitly from its detail view. Truncated native output is identified as incomplete. Reviewed cancellation emits only still-running owned operation IDs, skips operations that completed during the review and waits for native status updates. Cancellation can leave already-started remote or filesystem effects.

Native record calls publish busy state; pending import, label and destructive-review drafts publish their owning workspace's dirty state. The app shell must honor those states and call the component's `discardDrafts()` only after its existing successful native discard receipt. Failed writes preserve the draft and report the native error.

Verification uses actual bundled Material controls with an isolated real `WorkspaceStore`: `tests/workspace-records-render.test.ts` exercises managed selection, CSV export, date input, label saving, comparison and append-only restoration. `tests/activity-records-render.test.ts` verifies exact cancellation scope, metadata exclusions, changing operation filters and bilingual accessible labels. `tests/record-filters.test.ts` covers invalid/local dates, composed filtering, selection boundaries and nested differences. These deterministic fixtures do not certify provider permissions, platform secure storage or Windows installation.
