# GitHub selections and local Git

The native provider registry prepares local sources from selected repository, gist and pull-request records. It accepts approved host and record selectors, then reads the current provider account and actual record. The renderer receives a source summary and an opaque five-minute receipt. It cannot supply a clone URL, base repository or head commit as an authority claim.

Repositories bind their database identity and canonical credential-free HTTPS clone URL. Gists bind their exact ID and `https://gist.HOST/ID.git` URL. This gist mapping follows [the pinned GitHub CLI 2.102.0 implementation](https://github.com/cli/cli/blob/v2.102.0/pkg/cmd/gist/clone/clone.go#L98-L108), read on 2026-10-08; unexpected hosts, credentials, query strings and alternative source paths fail validation. Enterprise approval does not guarantee the server enables Gists.

Pull requests bind the actual base repository identity, visible number, provider database identity and exact head commit. The native target uses `refs/pull/NUMBER/head`, with the base branch retained for review. PR search selections retain their issue-record provenance, so issue and pull-request database IDs are verified against the corresponding provider endpoint.

The native-only `GitHubService.resolveProviderTarget(id)` repeats the stored authorization check and reads current provider/account records. Changed host, account, repository, source URL or head, an expired receipt, or context invalidation prevents its use. The Git service consumes this callback at its own reviewed local boundary. Revocation rejects an in-flight resolution, and context invalidation also prevents an in-flight provider read from issuing a fresh receipt.

Selected repositories and gists now offer **Clone locally** in their record details and a contextual Local Git/Local copy area. Opening it prepares the opaque source; it does not run Git or choose a directory. The embedded Source Control editor fixes the selected source and lets you choose the new folder name and clone options. **Review operation** uses the native parent-directory picker and produces an expiring exact Git review; **Apply reviewed operation** performs the clone and presents the actual result and repository snapshot. An existing destination is preserved. An explicit clean-source refresh replaces the old editor and revokes its source receipt. Drafts and active work remain visible to the owning GitHub workspace's close and account guards.

The repository's optional branch uses live choices from its approved host and canonical repository. The picker follows actual provider pages, searches through the native branch source and retains its selected branch while pages change. Branch reads keep the owning workspace busy. A failed branch read offers retry and preserves the default-branch clone option; it does not invent branches. Gists have no repository-branch REST source, so their contextual clone does not expose that picker. Pending provider tasks show compact clone/checkout controls; unrelated Source Control destinations appear only after a consumed task returns its local snapshot. Seeded fields are assigned once per source receipt, preserving edits while source activity or branch results rerender the wrapper.

Discarding first revokes the issued source receipt through an ID-only native cleanup action, then awaits the Git editor's unused-review cleanup. Failed cleanup keeps the editor open. Cleanup accepts no replacement host or action and needs no current provider/account read, so a changed context or expired unlock cannot strand an unused source receipt.

Provider API authentication identifies and reads the selected source. Native Git uses its configured transport credentials. Private cloning/fetching may require reviewed trust in configured credential helpers and Accounts → Set up Git authentication. The source receipt supplies no token to Git, and a successful API read does not establish that Git can fetch the repository. Credential, SSH, configuration and provider failures remain failed operations.

Tests use synthetic provider responses for canonical sources, Enterprise gist mapping, immutable identity/head drift, account/host changes, expiry, invalidation, rejected renderer claims and authorization on resolution. Compiled Material domain/editor fixtures verify selected IDs and hosts, fixed opaque sources without a URL input, reviewed target propagation, cleanup ordering and draft preservation after cleanup fails. They do not simulate a successful Git write. Separately, native Git consumer fixtures clone an actual isolated HTTPS Git repository and verify its files, remote and opaque local grant, source revalidation and review revocation. These are separate boundary proofs, not a live GitHub-to-local end-to-end result.

Selected PR details now offer **Check out locally**, also available in their contextual Local checkout area. The native source binds the actual base repository and exact selected head. Review chooses an existing local repository with an effective matching remote, requires clean staged/working/untracked state and prepares a fresh local branch. Apply fetches the exact provider reference into an owned temporary reference, verifies its commit and rechecks local state before a non-forced switch. It does not overwrite an existing branch or ignored-file collision. Cancellation and failed head verification can leave fetched Git objects or an explicitly reported retained reference; failed operations remain failed. The actual result includes the local repository snapshot. The embedded editor clears consumed provider scope before ordinary subsequent Git reviews.

Separate native HTTPS fixtures verify exact-head checkout, original permission rechecks, staged/unstaged/untracked/ignored content preservation, rejected remote/head changes, concurrent local changes, cancellation and reference cleanup. The compiled selected-record fixture verifies the visible PR number, retained database identity, approved host, opaque source and checkout task review propagation. These remain separate boundary proofs.

Repository Sync, issue-linked development, provider creation/revert follow-ups, full GitHub CLI clone/checkout option equivalence, private transport credentials and platform-specific launches remain separate work. In particular, this PR checkout does not implement the CLI's force, detached, submodule and worktree variants. No live remote write, private credential read, Windows launch, unified live GitHub-to-local result or all-six-handoff completion is claimed.
