# Personalization and local tools

Settings persist language (English, Hong Kong Cantonese, or both), independent playfulness levels from 1 to 5, emoji decoration, theme, density, theme seed colour, text size, font, app name, motion, narration, and five attention support switches. Both playfulness levels default to 5 and affect message voice while preserving factual text. Narration starts off; voice lists come from installed platform voices and refresh when enumeration changes. Missing saved voices fall back to automatic selection. Cantonese requires a platform Hong Kong Cantonese voice.

Personal vocabulary import and clear operate through the main-process local file picker and private application cache. No shipped mappings are supplied. The JSON contract is `{ "schemaVersion": 1, "entries": {} }`: entries are string-to-string replacements, with at most 256 entries, 128-character keys, and 256-character values. The complete UTF-8 payload is limited to 65,536 bytes and two object levels. Malformed UTF-8/JSON, duplicate keys, unsafe object keys, unknown fields or versions, control characters, and non-string replacement values are rejected before any application. The source path and vocabulary must never be included in exports, history, logs, telemetry, or model prompts. Rejected imports preserve the previous valid cache; explicit clear removes it.

Settings and local tools include isolated regex builders. The Utilities workspace separates regular expressions, local converters, and Ollama models/chat into tabs. See [converter capabilities](converters.md) and [Ollama boundaries](ollama.md).

The shared local presentation-mode service and encrypted TOTP service are wired into the application. Turning presentation mode on temporarily applies English, level-one playfulness and no personal vocabulary; turning it off restores the underlying preferences. Credential storage fails closed when operating-system encryption is unavailable. Cross-application propagation has service-level tests; a second built application has not been exercised. Scheduled settings, full every-element locking/recovery and the broader universal interface contract remain incomplete.

## Element appearance editor

The registered `mg-appearance` component takes an actual `HTMLElement` target and a stable `targetId`. Its own property search includes the anchored regex builder. Genuine Material controls edit default, hover, focus, pressed, and disabled states, typography size and line height, width and minimum height, spacing, corner radius, shadow, and transition duration. Hue, saturation, lightness, and alpha sliders provide continuous colour changes; six-digit hex input translates to RGB and HSL. Colour changes set component primary tokens and text colour; they do not universally recolour every internal token of every Material component.

Overrides persist locally in a validated, bounded per-element cache (100 stable IDs, 128 characters each, 131,072 serialized characters). `restoreAppearance(root)` restores validated state after stable targets render. Undo retains up to 30 edits during the current editor session; reset removes the element's overrides; export writes only the selected neutral appearance record. The editor is not Photoshop-equivalent: arbitrary vector layers, image processing, font asset installation, per-token recolouring, gradient editing, drag-based free transforms, imported style validation, and cross-app synchronization are not provided. Host-level width, padding and colour can behave differently from a component's internal layout; inspect the actual component after each edit.
