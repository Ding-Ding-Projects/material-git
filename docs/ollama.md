# Local Ollama workspace

`mg-ollama` is a dedicated Material composition. Mount it with the current `settings` and effective `schoolMode` properties. Its initial availability check uses the existing main-process `ollama('health')` route. Every request uses the fixed local endpoint `http://127.0.0.1:11434`; the renderer does not make network requests or accept arbitrary endpoints or commands.

If disconnected, the workspace names the local connection failure, offers Retry, and links the official setup documentation through `openExternal`. It does not install, launch, stop or configure the Ollama service. The installed-model collection comes from `models` and memory status comes from `running`. Installed models have an independent plain-text search with the adjacent isolated regex workbench and eight-item pagination. Cards show actual reported size, family, quantization, modification date and loaded-memory state; unknown values remain unavailable. Details use `show` and expose complete metadata only on request.

Download suggestions are explicitly curated registry identifiers, not invented installed models or verified current download sizes. The official library is linked for license and hardware review. Pull, copy and delete each require a local-change review. Copy requires a new bounded model identifier and refuses existing names in the UI. Delete requires two acknowledgement switches and a confirmation slider at 100; the handler independently checks all three, then calls the main-process deletion route with `confirmed:true`. Controls and handlers refuse re-entry during requests. Requests never run during rendering except the read-only initial health/model checks.

Chat selects an actually installed model, accepts a bounded user message, and sends real `chat` requests with bounded temperature and generated-token sliders. Once messages exist, the model selector remains fixed until the conversation is explicitly cleared. Messages exist only in renderer memory. Each request includes the most recent 20 messages and the new message; the visible conversation states this context limit. Errors retain the user's unsent message. Assistant Markdown is sanitized into a scriptless opaque-origin iframe. Links, images, scripts, forms and external requests are removed or blocked; no privileged provider markup is inserted into the application DOM. Responses report actual token count and elapsed duration where supplied; text exceeding 100,000 characters is explicitly marked as display-truncated.

The existing service returns complete JSON responses with `stream:false`. The UI therefore states that streaming, numerical transfer progress and cancellation are unavailable. Chat and pull have the service's 120-second deadline; other model actions have its eight-second deadline. A pull timeout does not prove that the local service stopped downloading, and the review explains this. Busy dialogs retain their real pending status with indeterminate progress rather than presenting fabricated percentages.

Primary action labels have English, Cantonese and bilingual copy controlled by settings. School mode forces English for this component. External identifiers, timestamps, model names and metadata remain factual. Descriptive secondary copy remains professional English; full localized prose and real built-artifact graphical verification are incomplete. Source compilation is not a substitute for an exercised local service or Electron interaction. No model downloads, copies, deletions or chat submissions were performed during implementation verification.
