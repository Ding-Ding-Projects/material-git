# 儲存庫同連結工作目錄管理

喺版本管理用「開啟儲存庫」揀原生目錄，或者用「新增儲存庫」同「複製儲存庫」確認新目的地。現有目錄唔會被覆寫。主程序保留所選儲存庫嘅授權，介面唔可以提供任意執行目錄。

「工作目錄」會顯示實際路徑、分支或者分離式狀態、HEAD、鎖定原因、過期登記原因同檔案變更。遺失、符號連結或者屬於另一個儲存庫嘅目錄會保留喺清單，並解釋點解無法使用。「開啟工作目錄」會重新核對所選一行嘅歸屬，再開啟嗰個確實目錄。有未完成操作草稿時唔可以切換。

新增工作目錄可以揀現有分支、由指定版本建立新分支，或者分離式檢出。原生選擇器指定上層目錄，執行前會再次核對目錄身份同新目的地冇被佔用。開啟新目錄之後，可以喺「維護」設定稀疏檢出目錄。

鎖定有獨立原因同解除鎖定操作。移動使用原生選擇器同全新目的地。修復已移動工作目錄會驗證 `.git` 檔案、共用管理目錄同原有路徑已經遺失；唔明確嘅歸屬或者確認後改變咗嘅管理資料會令操作停止。

移除會拒絕目前目錄、主要目錄、鎖定或者分離式目錄、進行中 Git 操作、有變更、未追蹤或者被忽略嘅檔案，以及需要額外檢查嘅稀疏或假設不變索引。所選 HEAD 必須已經合併入目前 HEAD，亦必須可以由現有遠端追蹤上游到達。冇足夠保存證據就唔會移除。冇強制選項，分支同共用暫存會保留。

上游證據只係本機遠端追蹤參照，唔代表剛剛向伺服器查證。需要最新證據時，先另外確認擷取指定遠端。移除確認本身唔會連線或者推送。

清理遺失工作目錄會先顯示 Git 嘅實際試行結果，只會移除過期管理登記。鎖定、目錄身份或者清單改變就要重新確認。確認五分鐘後過期，而且只可以用一次。取消或者失敗可能留下部分結果，要重新整理同檢查。

「維護」嘅「儲存庫概覽」顯示本機儲存庫結構、分支、HEAD、變更、進行中操作、淺層同稀疏狀態、遠端、上游差異、物件數量同大小，以及需要執行信任嘅設定。佢會指出保存變更、處理衝突、完整性檢查同復原記錄等下一步，但唔會自動修復、擷取、清理或者維護，亦唔會聲稱完整性已通過。

本機檢查唔會自動下載承諾物件。缺少物件會報告失敗，需要另外確認遠端操作。原生測試使用一次性儲存庫、裸遠端同連結工作目錄；Chromium 測試會操作真正 Material 控件同原生 Git。呢啲證據唔代表 Windows 安裝器、真實遠端或者完整外觀矩陣已驗證。
