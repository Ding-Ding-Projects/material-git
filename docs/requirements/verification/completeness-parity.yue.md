# 獨立完整性同反向回歸

公開功能識別碼：`completeness-parity`。分類：**驗證及證據**。

## 要求嘅行為

每個有使用者介面嘅應用程式同 GitHub Pages，都要獨立實作所有規範功能，唔推畀另一產品、共用網站、未來版本、隱藏路由或者佔位內容。逐介面人手清單列出每項功能，同實作、文章、本機化、儲存、重點驗證、建置產物操作同真實截圖連結。項目改動遇到缺少、過期或者未證明項目，要拒絕完成。可執行反向回歸逐項移除已聲稱項目，必須先失敗再通過。發佈級收尾另需人手深入稽核同逐次操作截圖記錄。

## 目前支援同設定

本清單列出全部 104 項公開中性要求，分開評估各介面，唔認證實作完全相同。

呢份係有明確範圍嘅實作評估，唔代表整項要求已經完成。各個表面嘅狀態分開記錄：**桌面：`partial`；網站：`unknown`；儲存庫：`partial`**。請睇[實作參考](../../requirements/README.md)同[完整清單](../../coverage/features.json)。控制項應該放喺擁有相關資料嘅工作目的地；主要介面必須係可以實際處理工作嘅空間。

## 控制項、預設值同限制

`check-feature-coverage.mjs` 固定 `104` 個必需識別碼同人手覆核嘅應用程式／網站／儲存庫適用表。結構驗證拒絕缺少列、證據、文章同冇根據嘅豁免。普通模式如實報告未解決項目；適用證據未齊，`--require-complete` 必須失敗。

## 失敗情況同剩餘工作

逐項補齊實作、本機化、儲存、驗證、操作同截圖；證據未支持前，嚴格完整性模式必須仍然失敗。

缺少本機依賴、作業系統功能、遠端權限同未有驗證證據要分開報告。無法使用嘅控制項要解釋真正原因，同時保留原有資料；唔可以用虛構範例或者假成功填補空狀態。

## 私隱

個人詞彙對照、認證資料、認證標頭、私鑰同環境變數原始內容，唔會放入普通匯出、歷史、日誌、截圖或者公開文件。本機記錄使用有版本同大小上限嘅結構；敏感匯出必須經專用檢查流程。涉及外部服務嘅要求，只記錄是否存在同狀態證據。

## 驗證

清單完整性同功能行為要分開測試。只有完成呢個功能嘅原始碼及驗證覆核、需要嘅儲存／重啟檢查、反向回歸檢查，以及同一版本實際建置介面嘅操作同真實截圖，先可以將呢項要求標示為完成。Linux 證據唔代表 Windows 安裝或者認證資料儲存正常。文章翻譯亦唔代表桌面同網站每個畫面都完成本機化。
