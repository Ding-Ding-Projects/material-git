# Sanitized project instruction summary

This is a project-specific summary of shared operating instructions, exported through the maintainer's canonical public-Markdown helper. It is not a complete mirror. A full-source export currently fails the canonical public guard; that missing mirror remains explicitly tracked in the requirements inventory.

## Scope and truthfulness

Build a complete productive desktop around real repositories, entities and contextual tasks. A command catalog, marketing page, generic command form, source-file count or schema registry does not prove a working feature. Apply every relevant requirement separately to the desktop, documentation site and repository; record genuinely narrower applicability and unresolved work explicitly.

## Implementation and verification

Use genuine registered Material Design 3 controls. Provide guided choices, inline explanations and validation, keyboard/touch paths, independent regex searches, typed native operations and exact review of destructive effects. Keep renderer privileges isolated. Preserve user work, bound subprocesses and network responses, and describe unavailable platform/service behavior honestly.

Run meaningful local checks before publication. Test negative boundaries and final built interactions with isolated profiles; capture only actual product windows at a known source revision and artifact hash. Screenshots, recording and design comparison must match the final interface. Source checks and mocks cannot establish live API permission or Windows installation behavior.

## Privacy and public records

Keep credentials, private signing material, personal vocabulary, machine/account/host details, raw environment values and private source paths out of published material, logs, ordinary exports, history, prompts and captures. Store sensitive records through the dedicated credential/encryption services. Public writing uses ordinary professional language and literal technical identifiers.

Keep documentation, requirement inventory, roadmap, handoff and closeout prompt current. Distinguish implementation support, integrated GUI behavior, live-service permission, platform limitations and missing evidence. Remote publishing, metadata updates, Discussions, Project records and release verification belong to the authorized publishing owner.

## Build and release

Use root build/dependency/installer entrypoints, pinned canonical downloads and verified digests. Windows delivery uses unsigned Squirrel artifacts and explicit restart for updates. CI builds/packages/publishes; do not invent CI test or lint results. Claim a release only after its exact source, run, installer and remote ref are verified.

## Conversation discipline

Follow the maintainer's canonical private conversation instructions without restating their vocabulary in public files. The neutral discipline block in AGENTS.md is copied exactly. Public-bound material must pass the canonical scan; a missing or stale private dictionary lock must be reported accurately without committing its terms or hash.
