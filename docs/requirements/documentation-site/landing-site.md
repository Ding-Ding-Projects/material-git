# A Material Design 3 GitHub Pages carrying every feature

Public feature identifier: `landing-site`. Category: **documentation-site**.

## Required behavior

Every public repository application ships a Material Design 3 GitHub Pages; private repositories are exempt from mandatory creation. Each existing GitHub Pages is a landing, documentation, download, status, settings, and link surface, says so visibly, and is never the primary runtime, a playable game, or an embedded imitation of the product. It strictly carries every user-facing feature in this catalogue as a GitHub Pages equivalent operating on its own content and per-visitor local storage, checked by a hand-written enumeration that fails the docs build when one is missing, and it is as customizable and tabbed as the application. It presents every feature the project has, bundles every asset locally with no CDN, hosted font, or analytics, states the version it documents, and never presents unreleased work as shipped.

## Current support and configuration

Documentation site rebuild is separate from the productive desktop and currently owner-private.

This is a scoped implementation assessment, not a claim that the whole requirement is finished. Surface states: **app: not-applicable; site: unknown; repository: not-applicable**. See [implementation reference](../../site.md) and the [complete inventory](../../coverage/features.json). Controls belong in the destination that owns the data; the primary UI must remain a productive task workspace.

## Failures and remaining work

Implement visitor-owned equivalents for every applicable feature, local assets/settings/docs and truthful documented version; verify deployment separately.

Missing native dependencies, OS facilities, remote permissions and verification are reported separately. Disabled or unavailable behavior must explain the actual cause and preserve the existing data; no sample entity or fake success fills an empty state.

## Privacy

Personal vocabulary mappings, credentials, authentication headers, private keys and raw environment values never enter ordinary exports, history, logs, captures or public documentation. Local records use bounded versioned schemas; any sensitive export requires its dedicated reviewed flow. For an external/service requirement, only presence/status evidence is recorded.
