# Support Tickets recovery desk

Public feature identifier: `support-tickets`. Category: **safety**.

## Required behavior

A locked-out person reaches **Support Tickets** from the unlock prompt, the lock setting, and Help: a playful local ticket desk whose resolution opens the application-data folder in the platform file manager with the exact path shown and copyable. It never deletes anything itself, and any in-application deletion goes through super confirmation. One plain line outside the comedy, unstyled by the funny level, states that nothing is sent anywhere and nobody is reading, and no real company's support branding or human response time is ever imitated.

## Current support and configuration

Local recovery ticket component can reveal/open the application-data location without contacting anyone.

This is a scoped implementation assessment, not a claim that the whole requirement is finished. Surface states: **app: partial; site: unknown; repository: not-applicable**. See [implementation reference](../../security.md) and the [complete inventory](../../coverage/features.json). Controls belong in the destination that owns the data; the primary UI must remain a productive task workspace.

## Controls, defaults and limits

Recovery uses the native service's actual application-data directory and platform file-manager opener. It never deletes the directory automatically or submits a message to a remote support team. The lock record and authenticator directory may differ; display the actual requested recovery target.

## Failures and remaining work

Drive Help/lock prompts, exact copy/open path, factual local-only notice and confirmed in-app deletion if offered.

Missing native dependencies, OS facilities, remote permissions and verification are reported separately. Disabled or unavailable behavior must explain the actual cause and preserve the existing data; no sample entity or fake success fills an empty state.
