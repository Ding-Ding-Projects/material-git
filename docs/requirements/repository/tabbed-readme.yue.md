# 精簡 README 同可收合參考

公開功能識別碼：`tabbed-readme`。分類：**儲存庫記錄**。

## 要求嘅行為

README 開頭顯示精簡索引、項目用途、安裝指令、GitHub Pages 連結同簡短目錄。長參考內容放入 `<details><summary>`，摘要要容易搵到。`CONTRIBUTING.md`、`LICENSE`、`SECURITY.md` 同 `CODE_OF_CONDUCT.md` 要真實並保持最新，讓 GitHub 喺 README 上方顯示對應分頁。首次讀者必需內容唔收合。

## 目前支援同設定

正更新精簡介紹、安裝、網站連結同收合參考；已加入社群文件。

呢份係有明確範圍嘅實作評估，唔代表整項要求已經完成。各個表面嘅狀態分開記錄：**桌面：`not-applicable`；網站：`not-applicable`；儲存庫：`partial`**。請睇[實作參考](../../../README.md)同[完整清單](../../coverage/features.json)。控制項應該放喺擁有相關資料嘅工作目的地；主要介面必須係可以實際處理工作嘅空間。

## 失敗情況同剩餘工作

核對新讀者必需內容一直可見，並確認 CONTRIBUTING／LICENSE／SECURITY／CODE_OF_CONDUCT 都係真實、目前文件。

缺少本機依賴、作業系統功能、遠端權限同未有驗證證據要分開報告。無法使用嘅控制項要解釋真正原因，同時保留原有資料；唔可以用虛構範例或者假成功填補空狀態。

## 私隱

個人詞彙對照、認證資料、認證標頭、私鑰同環境變數原始內容，唔會放入普通匯出、歷史、日誌、截圖或者公開文件。本機記錄使用有版本同大小上限嘅結構；敏感匯出必須經專用檢查流程。涉及外部服務嘅要求，只記錄是否存在同狀態證據。

## 驗證

清單完整性同功能行為要分開測試。只有完成呢個功能嘅原始碼及驗證覆核、需要嘅儲存／重啟檢查、反向回歸檢查，以及同一版本實際建置介面嘅操作同真實截圖，先可以將呢項要求標示為完成。Linux 證據唔代表 Windows 安裝或者認證資料儲存正常。文章翻譯亦唔代表桌面同網站每個畫面都完成本機化。
