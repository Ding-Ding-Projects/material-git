# 合併三個本機文字檔案

喺 **版本控制 → 修補檔 → 合併三個檔案**，用原生檔案選擇器揀目前版本、共同版本同傳入版本。桌面應用程式會用暫存副本執行 Git 三檔合併，顯示可編輯結果，再提供獨立嘅檢查步驟儲存新檔案。呢個流程唔會合併分支，亦唔會自動將結果加入暫存區。

## 選擇同檢查輸入

1. 用 **開啟儲存庫** 喺原生選擇器開啟本機儲存庫。
2. 開啟 **修補檔**，再揀 **合併三個檔案**。
3. 分別用 **選擇目前檔案**、**選擇共同版本檔案** 同 **選擇傳入檔案**。目前版本係你嘅內容；共同版本係雙方共同起點；傳入版本係要合併嘅另一份內容。
4. 預覽之前，可以用 **檢查輸入** 閱讀各個所選檔案。

每個輸入都要係一般 UTF-8 文字檔案，最多 2 MiB，唔可以包含 NUL 位元組或者已識別憑證。介面只會收到原生授權識別碼同檔案名稱，唔會由渲染程序提供檔案系統路徑。原生服務會記錄原始內容雜湊；檔案改變或者選擇到期時會拒絕操作，需要重新揀檔案。

預覽會建立由應用程式管理嘅暫存副本，完成後移除。預覽唔會改動原始輸入、儲存庫 HEAD、暫存區索引或者既有工作檔案。使用者檔案內容唔會當成普通歷史快照儲存。

## 選擇衝突顯示方式

| 控制項 | 選項同作用 |
| --- | --- |
| 衝突顯示方式 | **合併標記** 使用 `merge`；**包括共同版本** 使用 `diff3`；**精簡共同版本內容** 使用 `zdiff3`。 |
| 衝突處理方式 | **保留衝突** 保留未解決段落；**優先目前版本**、**優先傳入版本** 同 **合併雙方** 分別使用 Git 嘅 `ours`、`theirs` 同 `union` 處理方式。即使標記已移除，都要檢查結果。 |
| 差異演算法 | Histogram、Myers、Minimal 或 Patience。預設係 Histogram。 |
| 標記長度 | 3 至 64 嘅整數，預設係 7。 |

揀好選項後，按 **預覽檔案合併**。介面會顯示 Git 實際衝突數目；`127+` 代表回報數目已到 Git 上限。有衝突嘅結果仍然係有效預覽，唔代表衝突已解決。可以編輯 **合併結果** 解決衝突，或者捨棄結果。更改選項後，要重新執行預覽，先會得到對應新選項嘅結果。

結果最多 2 MiB，五分鐘後到期。二進位、無效 UTF-8 或者包含已識別憑證嘅內容，需要使用合適嘅受保護編輯器。

## 檢查同儲存新檔案

1. 編輯預覽，並檢查完整結果。
2. 揀 **檢查儲存新檔案**。結構化表單會帶入預覽識別碼、已編輯內容同建議新檔名。
3. 揀一個未使用嘅輸出檔名。如果仍有衝突標記，要解決標記，或者明確選取允許儲存未解決衝突標記。只移除標記唔代表內容已正確。
4. 按 **檢查操作**，再用原生資料夾選擇器揀輸出目錄。
5. 檢查列出嘅操作，再按 **套用已檢查操作**。

既有目的地永遠唔會被覆寫。原生服務會重新核對來源雜湊、儲存庫快照同輸出上層目錄，然後以獨佔建立方式寫入新檔案。如果檢查後目的地被佔用、來源改變、儲存庫狀態改變、輸出目錄改變或者預覽到期，需要重新檢查或者預覽。Git 中繼資料目錄唔可以用作目的地。

每個檢查記錄只可使用一次，成功儲存後亦會消耗該預覽。儲存會保留三個原始檔案、HEAD 同索引。如果輸出目錄喺工作樹入面，新檔案可能顯示為未追蹤修改；儲存唔會自動暫存或者提交。想要獨立結果，可以揀工作樹以外嘅資料夾。成功儲存後，桌面會清除結果嘅未儲存狀態。
