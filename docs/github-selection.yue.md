# 所選議題同拉取要求嘅身份

喺真實提供者清單揀議題或者拉取要求之後，桌面會用儲存庫顯示嘅編號讀取詳情同執行工作。提供者資料庫身份會另外保留，畀原生服務核對所選記錄仍然係同一項。資料庫 ID 唔會取代儲存庫畫面顯示嘅編號。

## 由所選記錄開始

1. 選取正確主機同儲存庫，再載入議題或者拉取要求清單。
2. 揀真正想檢查或者操作嗰行記錄。
3. 開啟詳情或者相關工作，檢查編輯器顯示嘅儲存庫同記錄。
4. 涉及修改時，先檢查實際操作，再套用。

所選工作會保留主機、儲存庫、顯示編號同可用提供者身份。顯示編號缺少或者無效時，介面會要求重新整理清單，唔會猜測端點。搜尋已合併拉取要求時，結果可能帶有議題資料庫身份，因為 GitHub 搜尋傳回議題形狀嘅記錄；原生核對會尊重呢個實體種類，而工作仍然使用拉取要求編號。

## 過期選擇同檢查記錄

選擇帶有提供者身份時，原生服務會重新讀取對應議題或者拉取要求，核對資料庫 ID 同顯示編號。如果唔相符，請求會停止，並要求重新整理同再次選取記錄。呢個核對涵蓋詳情讀取、相關工作，同修改檢查入面嘅提供者目標。

套用已檢查修改之前，會再次核對使用中帳戶、準備好嘅工作同提供者目標。所選身份、帳戶或者目標狀態改變時，需要重新檢查。套用只接受已檢查識別碼同確認，唔可以用新值取代已檢查目標。遠端實際權限仍然決定有效請求可唔可以成功。

呢啲核對唔會建立記錄、補上缺少權限，或者將舊記錄變成最新資料。應用程式話提供者目標改變時，要重新整理真實清單、檢查傳回記錄，再重新檢查操作。

## 驗證同限制

顯示選擇綁定由 `5b822458` 加入。`tests/github-selection.test.ts` 用受控制提供者回應測試原生服務，核對顯示編號同資料庫 ID 分開保留、已合併拉取要求搜尋嘅議題形狀結果、正確詳情端點，同身份改變時喺修改請求之前拒絕操作。另一個受控制個案亦核對，拉取要求修改通過身份驗證後，使用編號端點執行已檢查操作。

`tests/github-selection-render.test.ts` 會建置真正 Material 議題同拉取要求工作空間，透過已建置介面選取測試記錄、開啟關閉操作同要求檢查，再核對詳情及檢查請求保留編號、提供者身份、實體種類同主機。測試會核對冇發出套用請求，瀏覽器亦冇頁面錯誤。

呢啲結果證明使用測試資料時嘅原生驗證，同已建置介面選擇及檢查行為。唔代表真實 GitHub 寫入權限、公開儲存庫已執行修改、Windows 安裝，或者所有操作已經完成。現有 `e464ff70` 畫面集早過呢次身份綁定修改，唔可以改標籤當成新證據。已記錄 Windows 安裝程式亦獨立於較新來源工作。
